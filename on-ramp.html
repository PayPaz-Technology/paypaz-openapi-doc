On-Ramp 法币入金业务接口

以下业务接口都需要签名认证。公共 Header、签名算法见 认证 API 文档。 商户 ID 由 API Key 识别，无需在 Body 中传递。

对接流程

KYC 绑定在终端用户上（同一商户下固定 clientSubUserId），不绑定某一笔订单。 建单返回同时给出 订单 status 和 KYC kycStatus。 新用户订单一般为 KYC_REQUIRED，必须先走 initiate 把资料同步到 PayPaz。

引导用户只打开建单返回的 embedUrl（订单托管页）。 页内会完成剩余 KYC，通过后同一页继续选支付方式并下单。 
新用户:
  POST /onramp/kyc/initiate   （有 shareToken 则复用 Sumsub，否则用户填写）
       ↓
  POST /onramp/orders         → status=KYC_REQUIRED，返回 embedUrl
       ↓
  打开 embedUrl               → 页内补 KYC → 激活报价 → 支付

老用户（kycStatus=APPROVED）:
  跳过 initiate
       ↓
  POST /onramp/orders         → 通常直接 CREATED（已报价）
       ↓
  打开 embedUrl               → 支付
  • initiate 可在建单前或建单后调用。新用户建议先 initiate 再建单，打开托管页时 profile 已预填。
  • 报价、证件/活体、支付控件由托管页调用，商户不必对接这些内部接口。
  • 查单笔用 GET /onramp/orders/info?brokerOrderRef=；按时间列表用 POST /onramp/orders/query。

如何获取 shareToken

商户在自己的 Sumsub 后台开通 Share applicants data，用 App Token 调用 Sumsub POST /resources/accessTokens/shareToken。 forClientId 由 PayPaz 商务提供，不要填商户自己的 clientId。 token 一次性、短 TTL，生成后立刻交给 initiate，不要落库。

请求体
{
  "applicantId": "6a41dab9f1fa3809f65ceae6",
  "forClientId": "<PayPaz 提供的 Sumsub clientId>",
  "ttlInSecs": 600
}
名称类型必选说明
applicantIdstringtrue商户 Sumsub 侧该申请人的 ID（Dashboard 或 Applicant API 返回）
forClientIdstringtrue接收方 Sumsub clientId，由 PayPaz 商务提供；不要填商户自己的 clientId
ttlInSecsnumber否token 有效秒数，建议 600（10 分钟）；过期需重新生成
curl 示例（需按 Sumsub 规则对 timestamp+METHOD+path+body 做 HMAC-SHA256 hex 签名）
TS=$(date +%s)
BODY='{"applicantId":"YOUR_APPLICANT_ID","forClientId":"PAYPAZ_CLIENT_ID","ttlInSecs":600}'
SUMSUB_PATH='/resources/accessTokens/shareToken'
SIG=$(python3 -c "import hmac,hashlib,os,sys
secret=os.environ['SUMSUB_SECRET_KEY']
ts,method,path,body=sys.argv[1:]
print(hmac.new(secret.encode(), (ts+method+path+body).encode(), hashlib.sha256).hexdigest())" \
  "$TS" POST "$SUMSUB_PATH" "$BODY")

curl -s -X POST "https://api.sumsub.com$SUMSUB_PATH" \
  -H "Accept: application/json" \
  -H "Content-Type: application/json" \
  -H "X-App-Token: $SUMSUB_APP_TOKEN" \
  -H "X-App-Access-Ts: $TS" \
  -H "X-App-Access-Sig: $SIG" \
  -d "$BODY"
成功响应（取 token 作为 initiate 的 shareToken）
{
  "token": "_act-sbx-jwt-eyJhbGciOiJub25lIn0...."
}

沙盒与生产都使用 https://api.sumsub.com，环境由 App Token 前缀区分（沙盒一般为 sbx:）。申请人须已在商户 Sumsub 侧审核通过，且 verification level 含证件核验（不只是活体）。

5. Sumsub Share Token 全流程

商户自己已有 Sumsub 账号、且终端用户已在商户侧完成 KYC 时，可以用 Share Token 把该申请人的身份数据一次性共享给 PayPaz（Legend），用户在托管页无需重复上传证件和做活体。

角色是谁做什么
Donor（数据提供方）商户自己的 Sumsub 账号用自己的 App Token 生成 share token
Recipient（数据接收方）PayPaz / Legend 的 Sumsub 账号凭 share token 拉取该申请人的证件与核验结果
 
商户 Sumsub（Donor）                                  PayPaz / Legend（Recipient）
 ① 申请 App Token（勾选「共享申请人数据」）
 ② 取 applicantId（该申请人已审核通过 GREEN）
 ③ POST /resources/accessTokens/shareToken  ──┐
      forClientId = PayPaz 的 clientId        │ token 一次性、TTL 默认 600s
 ④ POST /onramp/kyc/initiate（带 shareToken）─┘──→ Legend 复用证件，免二次 KYC
 ⑤ POST /onramp/orders → 引导用户打开 embedUrl
Step 1 · 申请 API Token

登录 cockpit.sumsub.com， 左侧菜单 开发空间（Dev Space）→ 应用令牌（App Tokens），点击新建令牌。

  • 先确认右上角的 沙盒 / 生产 环境开关，令牌与环境绑定：沙盒令牌查不到生产申请人，反之亦然。
  • 创建完成会得到一对凭据：App Token（形如 sbx:xxxx.yyyy，沙盒前缀 sbx:）和 Secret Key。
  • Secret Key 只在创建时显示一次，务必立刻保存；丢失只能重新生成令牌。
  • 建议按环境各建一个令牌，并用环境变量注入，不要提交进代码仓库。
凭据用途
App Token请求头 X-App-Token，标识商户身份与环境
Secret Key本地做 HMAC-SHA256 签名，写入 X-App-Access-Sig，不参与传输
Step 2 · 务必勾选「可重用身份」权限
创建令牌时，在权限列表里找到 可重用身份（Reusable KYC） 分组， 勾选 共享申请人数据（Share applicants data）。 没有这个权限，POST /resources/accessTokens/shareToken 会直接被拒（403 / permission denied）， 且报错信息不会提示是权限问题。
  • 若还想用 Sumsub 的申请人资料自动填充 initiate 的 profile（见 Step 5），同时勾选 申请人（Applicants）读取 权限，用于调用 GET /resources/applicants/{id}/one。
  • 令牌权限可以事后在应用令牌详情里修改；改完立即生效，无需换 token。若无法编辑，删除后重建并同步更新环境变量。
  • 沙盒和生产的令牌权限是各自独立的，沙盒调通后上生产要再检查一次。
Step 3 · 准备 applicantId 与 forClientId
参数从哪来注意
applicantId Sumsub 后台申请人详情页，或 POST /resources/applicants 创建时返回，也可用 GET /resources/applicants/-;externalUserId={你的用户ID}/one 反查 必须与 App Token 同环境
forClientId PayPaz 商务提供的接收方 clientId（例如 legendtrading_96360） 不要填商户自己的 clientId（后台 URL 上的 clientId= 是自己的，填了会共享给自己，等于无效）
ttlInSecs 自定义，建议 600 过期即失效，需重新生成

申请人还必须满足：审核结果为 reviewStatus=completed 且 reviewAnswer=GREEN， 且其 verification level 包含证件核验（只有活体的 level 共享过去仍会被要求补件）。

Step 4 · 签名规则

Sumsub 用请求级签名，签名串按顺序拼接后做 HMAC-SHA256，输出 hex（不是 Base64）：

signContent = timestamp + METHOD + path + body
signature   = hex( HMAC_SHA256(signContent, SECRET_KEY) )
Header值
X-App-TokenApp Token
X-App-Access-Ts秒级 Unix 时间戳，与签名串里的 timestamp 必须是同一个值
X-App-Access-Sig上面算出的 hex 签名
Content-Type有 body 时为 application/json
  • METHOD 大写；path 是不含域名的路径，带 query 时 query 也要算进去。
  • body 必须与实际发出的字节完全一致：先序列化成字符串，再把同一个字符串同时用于签名和发送，不要分别 dump 两次。
  • 时间戳偏差过大会被拒，服务器时钟需同步。
Step 5 · Python 示例
1）签名与生成 share token（可直接运行）
#!/usr/bin/env python3
"""生成 Sumsub share token，交给 PayPaz /onramp/kyc/initiate 使用。"""
import hashlib, hmac, json, os, time
import requests

SUMSUB_BASE_URL = os.environ.get("SUMSUB_BASE_URL", "https://api.sumsub.com")
APP_TOKEN     = os.environ["SUMSUB_APP_TOKEN"]       # sbx:xxxx.yyyy（沙盒）
SECRET_KEY    = os.environ["SUMSUB_SECRET_KEY"]      # 创建令牌时只显示一次
APPLICANT_ID  = os.environ["SUMSUB_APPLICANT_ID"]    # 商户侧已审核通过的申请人
FOR_CLIENT_ID = os.environ["SUMSUB_FOR_CLIENT_ID"]   # PayPaz 提供，勿填自己的 clientId
TTL_SECS      = int(os.environ.get("SUMSUB_TTL_SECS", "600"))


def _sign(ts, method, path, body=""):
    """HMAC-SHA256(secret, ts + METHOD + path + body)，hex 输出。"""
    payload = f"{ts}{method.upper()}{path}{body}"
    return hmac.new(SECRET_KEY.encode(), payload.encode(), hashlib.sha256).hexdigest()


def sumsub_request(method, path, body=""):
    ts = str(int(time.time()))
    headers = {
        "Accept": "application/json",
        "X-App-Token": APP_TOKEN,
        "X-App-Access-Ts": ts,
        "X-App-Access-Sig": _sign(ts, method, path, body),
    }
    if body:
        headers["Content-Type"] = "application/json"
    return requests.request(
        method,
        SUMSUB_BASE_URL.rstrip("/") + path,
        headers=headers,
        data=body.encode("utf-8") if body else None,
        timeout=30,
    )


def create_share_token():
    path = "/resources/accessTokens/shareToken"
    # 同一个 body 字符串既用于签名也用于发送，避免两次序列化产生差异
    body = json.dumps(
        {"applicantId": APPLICANT_ID, "forClientId": FOR_CLIENT_ID, "ttlInSecs": TTL_SECS},
        separators=(",", ":"),
    )
    resp = sumsub_request("POST", path, body)
    if resp.status_code >= 400:
        raise RuntimeError(f"shareToken HTTP {resp.status_code}: {resp.text[:500]}")
    token = resp.json().get("token")
    if not token:
        raise RuntimeError("Sumsub 未返回 token: " + resp.text[:300])
    return token

def to_initiate_profile(applicant, email):
    info  = applicant.get("info") or {}
    fixed = applicant.get("fixedInfo") or {}
    # 住址优先取 fixedInfo（商户填报，Sumsub 视为可信），证件地址兜底
    addrs = (fixed.get("addresses") or info.get("addresses") or [{}])
    addr  = addrs[0] if addrs else {}
    return {
        "email": email,
        "firstName": info.get("firstNameEn") or info.get("firstName"),
        "lastName": info.get("lastNameEn") or info.get("lastName"),
        "birthdate": info.get("dob"),                          # YYYY-MM-DD
        "countryIso2Code": iso3_to_iso2(addr.get("country")),  # 居住国
        "state": addr.get("stateEn") or addr.get("state"),
        "city": addr.get("townEn") or addr.get("town"),
        "address": addr.get("streetEn") or addr.get("street"),
        "zipCode": addr.get("postCode"),
        "citizenshipIso2Codes": iso3_to_iso2(info.get("nationality")),
        "placeOfBirth": iso3_to_iso2(info.get("countryOfBirth") or info.get("nationality")),
    }
  • Sumsub 返回 ISO3 国家码（SGP），initiate 要的是 ISO2（SG），需要自己转换（pycountry 或维护映射表）。
  • Legend 侧只接受拉丁字符，优先取 Sumsub 的 *En 转写字段（townEn=KOELN 而不是 town=KÖLN）。
  • countryIso2Code 是居住国，必须与 state / city / zipCode 自洽；国籍走 citizenshipIso2Codes，两者可以不同。
  • 拿不到住址时，整块使用一组自洽的兜底地址，不要逐字段兜底，否则会拼出「国家 DZ + 城市 Singapore」这种互相矛盾的组合被拒。
