1. 业务说明

On-Ramp 用于商户终端用户以法币购买 USDT（银行转账 / 信用卡 / Apple Pay / Google Pay）。 商户侧对接尽量简单：按 USDT 数量建单（无论是否已完成 KYC 均先落单）， 支付与币种选择在 Paypaz 支付托管页完成；未完成 KYC 时引导用户打开 KYC 托管页， 认证通过后可从该页「继续支付」回到同一笔未完成订单。

鉴权：以下接口均需签名认证，商户身份由 API Key 识别（无需再传商户 ID）。 公共 Header、签名算法见 认证 API 文档。 请为 API Key 开通 onramp 权限。建议透传终端用户公网 IP：Header X-User-Ip。

    商户实现回调接口，接收订单入账完成通知。

4. POST 创建 On-Ramp 订单 签名

为指定客户子账号创建买币订单。入参以 USDT 数量 为准； 法币币种与支付方式由用户在支付托管页选择。 无论 KYC 是否完成，均先保存订单。 已完成 KYC：status=awaiting_payment 并返回 checkOutUrl； 未完成 KYC：status=awaiting_kyc，需引导用户完成 KYC 后再支付。

POST/t-api/openapi/v1/op/openapi/onramp/orders

Body 请求参数

{
  "clientSubUserId": "csub_abc123",
  "clientOrderNo": "ONRAMP-20260724-0001",
  "usdtAmount": "100.00"
}

CreateOnRampOrderRequest 属性

名称类型必选说明
clientSubUserIdstringtrue客户子用户唯一标识（商户侧）
clientOrderNostringtrue商户订单号，唯一键，幂等
usdtAmountstringtrue入金数量，单位 USDT，须 > 0，精度以正式规则为准

商户 ID 由 API Key 识别，无需在 Body 中传递。

    "kycUrl": null,

}

支付托管页行为（Paypaz 实现，商户无需开发）

  • 展示订单 USDT 数量
  • 法币币种可选（以结算服务支持列表为准）
  • 支付方式：银行卡、Apple Pay、Google Pay（及平台开通的卡支付）
  • 用户确认后完成付款；后续兑币、打币、入账由 Paypaz 与结算服务处理

5. POST 同步个人资料（KYC） 签名

当订单状态为 awaiting_kyc 时调用。商户提交已收集的用户信息并关联订单号， Paypaz 落库并预填至结算服务；返回 KYC 托管页 URL。 用户打开后可看到已有信息，补全其余项并完成证件/活体等认证。 KYC 通过后，页面提供「继续支付」，跳转至该订单的支付托管页。

KYC 网页采用：结算服务 API + 身份认证 SDK v2（含完整证件核验 / 活体 / 地址证明重试流程）。

POST/t-api/openapi/v1/op/openapi/onramp/kyc/profile

Body 请求参数

{
  "orderNo": "PZ20260724-00123",
  "clientOrderNo": "ONRAMP-20260724-0001",
  "clientSubUserId": "csub_abc123",
  "email": "taro.tanaka@example.com",
  "phone": "+819012345678",
  "firstName": "Taro",
  "lastName": "Tanaka",
  "birthdate": "1990-04-12",
  "nationality": "JP",
  "countryIso2Code": "JP",
  "state": "",
  "city": "Tokyo",
  "address": "1-1 Chiyoda",
  "zipcode": "100-0001"
}

SyncKycProfileVO 属性

名称类型说明
orderNo / clientOrderNostring关联的订单号
kycUrlstringKYC 托管页链接，请引导终端用户打开
orderStatusstring当前仍为 awaiting_kyc（通过后变为 awaiting_payment）

KYC 托管页行为

  • 展示商户已同步的个人信息（预填）
  • 引导用户补全缺失字段
  • 通过身份认证 SDK v2 完成证件拍摄、活体、地址证明（含重试）
  • 提交后进入审核
  • 审核通过后：展示「继续支付」按钮，跳转至原订单的支付托管页（checkOutUrl），订单状态由 awaiting_kyc 变为 awaiting_payment
  • 无需商户再次调用创建订单接口

8. 商户入账 Webhook

商户需在 Paypaz 后台配置 HTTPS 回调地址，并订阅 On-Ramp 入账事件。 签名验证方式与现有 Webhook 相同，详见 webhook 说明。

到账依据：仅以 transaction.onramp.completed 作为用户 USDT 入账完成的通知。 请勿以「用户已提交汇款」或支付页中间态作为最终成功。

建议订阅事件

eventType说明商户动作
transaction.onramp.completed 链上确认完成，USDT 已入账 必须处理：更新业务订单为成功
transaction.onramp.failed 失败 通知用户失败，允许重新建单
transaction.onramp.expired 订单过期未支付 关闭待支付单

completed 请求体示例

{
  "eventType": "transaction.onramp.completed",
  "data": {
    "orderNo": "PZ20260724-00123",
    "clientOrderNo": "ONRAMP-20260724-0001",
    "clientSubUserId": "csub_abc123",

    "usdtAmount": "100.00",
    "fiatCurrency": "JPY",
    "fiatAmount": "15600",
    "paymentMethod": "bank",
    "tokenId": "USDT",
    "chainId": "TRON",
    "txId": "abc123def456...",
    "walletAddress": "TX3ogswu...",

附录 A · 订单状态

status含义

附录 C · 注意事项

  • 建单金额单位为 USDT；用户实付法币金额在托管页按所选币种与报价计算。
  • 未完成 KYC 时也会先创建并保存订单（awaiting_kyc），请妥善保存 orderNo。
  • KYC 通过后由用户在 KYC 页点击「继续支付」进入同一笔订单支付，无需再次创建订单。
  • 必须以 Webhook completed 或查询到 status=completed 作为业务成功依据。
  • KYC 与支付均为 Paypaz 托管页，商户无需对接结算服务 SDK；只需打开我们返回的 URL。
  • clientOrderNo 请保证商户内唯一，用于幂等与对账。
  • 建议配置 Webhook；未配置时可轮询订单详情 / 列表。
