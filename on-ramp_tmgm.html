On-Ramp 法币入金业务接口

以下业务接口都需要签名认证。公共 Header、签名算法见 认证 API 文档。 商户 ID 由 API Key 识别，无需在 Body 中传递。

对接流程

KYC 绑定在终端用户上（同一商户下固定 clientSubUserId），不绑定某一笔订单。 建单返回同时给出 订单 status 和 KYC kycStatus。 新用户订单一般为 KYC_REQUIRED，打开托管页完成身份验证即可。

引导用户只打开建单返回的 embedUrl（订单托管页）。 页内会完成剩余 KYC，通过后同一页继续选支付方式并下单。 
新用户:
  POST /onramp/orders         （可带 profile 预填）→ status=KYC_REQUIRED，返回 embedUrl
       ↓
  打开 embedUrl               → 页内补 KYC → 激活报价 → 支付

老用户（kycStatus=APPROVED）:
  POST /onramp/orders         → 通常直接 CREATED（已报价）
       ↓
  打开 embedUrl               → 支付
  • 建单时可传 profile，打开托管页时资料已预填，减少用户填写。
  • 报价、证件/活体、支付控件由托管页调用，商户不必对接这些内部接口。
  • 查单笔用 GET /onramp/orders/info?brokerOrderRef=；按时间列表用 POST /onramp/orders/query。

1. POST 创建 On-Ramp 订单

按净加密数量建单。法币与支付方式由用户在托管页选择。 无论 KYC 是否完成都会落单：未通过时 status=KYC_REQUIRED； 已通过（kycStatus=APPROVED）时会尝试激活报价，成功则多为 CREATED。

特殊说明

  • status=KYC_REQUIRED 时订单已创建成功（HTTP 200）。打开 embedUrl 即可。

3. POST 查询 On-Ramp 订单列表

按当前 API Key 所属商户分页查询，按 createdAt 倒序。 需要 onRamp 权限。

POST/t-api/openapi/v1/op/openapi/onramp/orders/query

Body 请求参数

{
  "clientSubUserId": "csub_abc123",
  "brokerOrderRef": "ONRAMP-20260825-0001",
  "paypazOrderId": "PZO2091798976151027712",
  "status": "COMPLETED",
  "startTime": 1721606400000,
  "endTime": 1724198400000,
  "pageNo": 1,
  "pageSize": 20
}

QueryOnRampOrderRequest 属性

名称类型必选说明
clientSubUserIdstringfalse按客户过滤；不传则查商户下全部。传了但不存在该子用户则报错
brokerOrderRefstringfalse商户订单号（精确匹配）
paypazOrderIdstringfalsePayPaz 订单号（精确匹配）
statusstringfalse订单状态，如 CREATED / COMPLETED，见下方状态表
startTimeinteger(int64)见说明创建时间起（13 位毫秒）。与 endTime 须同时传或同时不传
endTimeinteger(int64)见说明创建时间止（13 位毫秒）。都不传则默认 UTC 当天 00:00:00～23:59:59.999
pageNointegerfalse从 1 开始，默认 1
pageSizeintegerfalse1–100，默认 20
  • 时间窗口按订单 createdAt 过滤，最长 30 天。
  • 只传 startTime 或只传 endTime 会报错（500105036）。
  • 时间戳不是 13 位毫秒会报错（500105039）；开始大于结束（500105037）；间隔超过 30 天（500105038）。
  • 列表项字段与创建/详情的 OnRampOrderOpenApiVO 相同，但列表不额外查 KYC，kycStatus / kycMode 可能为空。需要 KYC 状态请用详情接口。

4. 商户 Webhook

在 PayPaz 后台配置 HTTPS 回调地址，并勾选 On-Ramp 事件。签名、重试、响应要求与现有充提 Webhook 相同，见 webhook 说明。

到账依据：仅以 transaction.onramp.completed 作为用户加密货币入账完成的通知。 托管页支付成功、Legend 受理、3DS 通过都不是最终成功。

信封结构：{ "eventType": "...", "data": { ... } }。请求头为 PAYPAZ-WEBHOOK-SIGN、PAYPAZ-WEBHOOK-TIMESTAMP。

建议订阅事件

eventType何时触发商户动作
transaction.onramp.completed 链上确认完成，USDT 已入账（Cobo 入账成功后） 必须处理：把业务订单记为成功。可按 brokerOrderRef 幂等
transaction.onramp.failed 订单进入终态 FAILED（支付被拒、风控取消、合规核验失败、打币失败等） 通知用户失败，允许用新的 brokerOrderRef 重新建单。同一笔不会再变 COMPLETED
transaction.onramp.expired 支付窗口到期，且订单仍为 CREATED / AWAITING_PAYMENT（用户未完成支付） 关闭待支付单。若用户在过期后仍完成了支付，后续可能继续推进，以查单 / completed 为准

未支付就关掉页面、银行卡限额（如 Legend 305100）、3DS 取消等不会立刻发 failed：订单仍可在过期前重试；超时未付才走 expired。

completed 请求体
{
  "eventType": "transaction.onramp.completed",
  "data": {
    "paypazOrderId": "PZO2095033615367933952",
    "brokerOrderRef": "ONRAMP-20260902-0001",
    "cryptoCurrency": "USDT",
    "chain": "TRON",
    "cryptoAmount": "50",
    "fiatCurrency": "USD",
    "fiatAmount": "53.59",
    "paymentMethod": "credit_card",
    "paypazFee": "0.15",
    "completedAt": 1787558800000
  }
}
字段说明
paypazOrderIdPayPaz 订单号
brokerOrderRef商户侧订单号，幂等键
cryptoAmount用户下单净到账数量（不是链上实到）
fiatAmount应付法币（含加点）
paymentMethodcredit_card / google_pay / apple_pay
completedAt完成时间，毫秒时间戳
failed 请求体
{
  "eventType": "transaction.onramp.failed",
  "data": {
    "paypazOrderId": "PZO2095033615367933952",
    "brokerOrderRef": "ONRAMP-20260902-0001",
    "failReason": "PAYMENT_REJECTED",
    "failedAt": 1787558800000
  }
}
failReason含义
PAYMENT_REJECTED支付被拒或 Legend 成交失败（卡被拒、交易失败/取消）
RISK_CANCELLED风控取消
VERIFICATION_FAILED支付后合规核验未通过
VERIFICATION_ABANDONED合规补充核验被放弃
CRYPTO_TRANSFER_FAILED法币已扣、加密货币未打出，需人工介入

failReason 可能为空；对接时以 eventType 为准，reason 仅作展示与客服排查。

expired 请求体
{
  "eventType": "transaction.onramp.expired",
  "data": {
    "paypazOrderId": "PZO2095033615367933952",
    "brokerOrderRef": "ONRAMP-20260902-0001",
    "expiredAt": 1787429849234

订单与 KYC 状态

订单 status

status含义
KYC_REQUIRED未完成 KYC，订单已保存，尚未报价/开地址
ACTIVATINGKYC 已通过，正在开地址 / 取报价
CREATED已激活，可进入收银台
AWAITING_PAYMENT用户已进入支付
PAYMENT_PROCESSING支付已受理
FIAT_RECEIVED法币已到账
CRYPTO_TRANSFERRING打币中
PENDING_VERIFICATION合规补充验证
COMPLETED完成
FAILED失败
EXPIRED过期

常见流转：KYC_REQUIRED →（KYC 通过）→ CREATED → AWAITING_PAYMENT → PAYMENT_PROCESSING → CRYPTO_TRANSFERRING → COMPLETED
